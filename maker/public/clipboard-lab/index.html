02 · 复制策略

    1

    原生 ClipboardItem（标准图像 MIME）

    image/gif · Promise 包装的 Blob

    等待源就绪

    真正调用 navigator.clipboard.write，写入当前源的标准图像 MIME。数据用 Promise.resolve(blob) 包装，写入调用发生在点击处理器的同一任务内。

    不支持的尝试不会静默跳过：NotAllowedError、NotSupportedError 等会原样显示。supports() 结果只代表浏览器层面，见右栏。

    2

    自定义 ClipboardItem（web image/*）

    web image/gif · 原始 Blob 字节

    等待源就绪

    使用 web image/gif 或 web image/webp 自定义类型，写入与源文件完全相同的 Blob 字节，不做转码。

    只有理解这个自定义类型的接收方才能读到它；普通应用可能完全忽略该类型。

    3

    text/html + Data URL 图片

    text/html · <img src="data:…">

    等待源就绪

    把原始文件转成 base64 Data URL，嵌入完整 HTML 图片标签后写入 text/html。

    接收方可能把 HTML 当成富文本或图片处理；是否保留动画取决于目标应用，而不是浏览器。

    4

    text/html + 绝对 URL / blob URL

    text/html · 远程或 blob 地址

    等待源就绪

    HTML 里只放一个绝对地址：示例文件使用同目录的 HTTP 地址；本地上传使用 blob: URL。

    上传文件的 blob URL 只在当前页面打开期间有效，接收方也可能拒绝解析 blob: 地址；示例 HTTP 地址还取决于接收方能否访问网络。

    5

    仅 image/png 静态备用图

    image/png · 第一帧

    等待源就绪

    只写入提前准备好的 PNG。它来自第一帧，是普通静态图片。

    这是兼容性最高的路径，但动画一定丢失。目标应用拿到的是静态 PNG。

    6

    自定义格式 + image/png

    web image/gif + image/png

    等待源就绪

    同一个 ClipboardItem 同时放入自定义动图类型和静态 PNG，让接收方自己挑选能理解的类型。

    原生应用很可能只取 PNG；你看到的可能是静态图，而不是动画。

    7

    自定义格式 + text/html Data URL

    web image/gif + text/html

    等待源就绪

    同时提供自定义 Blob 类型和 Data URL HTML。两条路径都保留原始字节或完整内嵌数据。

    仍没有任何规范保证接收方会识别自定义类型；HTML 路径是否被采用也取决于目标应用。

    8

    text/html Data URL + image/png

    text/html + image/png

    等待源就绪

    同时写入富文本 HTML 和静态 PNG，覆盖偏向 HTML 或偏向位图的接收方。

    原生应用若选择 PNG，只会得到静态图；HTML 路径也可能被目标应用忽略。

    9

    旧式 copy 事件 + execCommand

    text/html · 已弃用 / 实验性

    等待源就绪

    临时插入一个可编辑节点，监听 copy 事件并调用 clipboardData.setData('text/html', dataUrlHTML)，最后执行 document.execCommand('copy')。

    这是已弃用、实验性的路径。操作结束后会移除临时节点和监听器，并恢复之前的焦点与选区。

    10

    text/plain 源 URL（仅链接）

    text/plain · 不是图片数据

    等待源就绪

    只写入一个纯文本 URL：示例文件写同目录 HTTP 地址，上传文件写当前页面的 blob URL。

    这不是图片数据。粘贴到大多数应用只会得到一条链接；上传文件的 blob URL 关闭页面后失效。
